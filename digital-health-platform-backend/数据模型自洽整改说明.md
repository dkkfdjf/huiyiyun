# 数据模型自洽整改说明

> 背景:初版建表/种子"只建实体、没把关系喂饱",导致切到不同药企/城市/角色时常看到空数据,
> 联系人与账号脱节、销售流水归属错误等。本次对**种子数据 + 组织-账号关系 + 城市维度**做一次自洽整改。
> 适用范围:`DataInitializer` 种子、药企/机构 Service、城市看板。建表 SQL(V1)未改。

---

## 一、审计发现(整改前的问题)

| # | 问题 | 证据 | 后果 |
|---|------|------|------|
| 1 | 扬子江药业是"空壳" | 种子建了公司(audit=1),但药品/网点/库存/政策/销售全是华润;无绑定账号 | 选扬子江看什么都空,且无法登录 |
| 2 | 销售/补货硬编码 `companyId=1L` | `salesAndReplenish(Long[] drugs, Long... locations)` 不收 companyId,内部写死 1L;调用处还把 `huarun` 当第 6 个网点塞进 varargs | 扬子江销售无法正确归属(潜在 bug) |
| 3 | 西安全空 | 建了西安,无网点无机构 | "查城市没用" |
| 4 | 核心反馈流零种子 | 无 `drug_demand` 种子 | 头牌功能登录即空,看板计数全 0 |
| 5 | 药品 producer 写死"华润三九" | `drugs()` 内硬编码 | 扬子江药品也会标成华润三九 |
| 6 | 药企/机构建组织不带账号 | `PharmaCompanyService.save` / `InstitutionService.save` 只 insert 组织;`DoctorService.save` 却是建账号+档案一体 | 联系人是飘的 free-text,与 user 表脱节 |

> 保留项:`示例待审医药公司`(audit=0)是有意的审核演示数据;`login_log/operation_log/error_log` 为运行期日志,空着正常。

## 二、整改内容

### 1. 种子自洽(`DataInitializer.java`)
- **扬子江补成第二家完整药企**:4 个药品(独立批准文号 `Z2011000x`/`H20110004`,避免与华润唯一键冲突)、2 个网点(含**西安**「扬子江西安店」)、库存(蓝芩口服液 15/40 制造预警)、政策、销售/补货流水。
- **扬子江登录账号**:`company02 / company123 / 李伟`,绑定扬子江 → 消除空壳,可登录演示。
- **修 `salesAndReplenish` 硬编码**:签名改为 `(Long[] drugs, Long companyId, Long... locations)`,按公司正确归属;调用处不再误把公司 id 当网点。
- **producer 参数化**:`drugs(Long companyId, String producer, Object[][] defs)`,华润=华润三九、扬子江=扬子江药业。
- 灭审计 #1 #2 #3 #5。

### 2. 临床反馈种子(灭 #4)
新增 5 条 `drug_demand`,覆盖全状态,挂在真实医师/药企上:

| # | 提交医师 | 药品 | 关联药企 | 状态 |
|---|---------|------|---------|------|
| 1 | 陈明(协和) | 阿莫西林 | 华润 | 0 待处理(紧急) |
| 2 | 陈明(协和) | 氨氯地平 | 华润 | 1 处理中 |
| 3 | 市第一医师 | 蓝芩口服液 | 扬子江 | 2 已满足 |
| 4 | 省人民医师 | 奥美拉唑 | 华润 | 3 已驳回 |
| 5 | 陈明(协和) | 盐酸氨溴索(手填) | 未关联池 | 0 待处理 |

> `doctor_id` 取医师**档案 id**(与运行时 `DrugDemandService.create` 一致),`handler_id` 取药企账号 id。

### 3. 城市覆盖看板(灭"查城市没用")
- `CityService.coverage()`:每城市汇总 **网点数 / 机构数 / 覆盖药企数 / 累计销售额**(销售额经 `sales_location.city_id` 桥接,因 `sales_record` 无城市字段)。全量内存聚合,**不缓存**(看板始终最新)。
- `CityController`:`GET /api/v1/cities/coverage`(仅管理员)。
- 前端 `CityView.vue`:从纯 CRUD 升级为 KpiCard + 网点/机构分布条形图(CoverageBars)+ 覆盖明细表,底部保留城市增删改。

### 4. 组织-账号关系对齐(灭 #6,对齐 `DoctorService`)
- **药企**(`PharmaCompanyService.save`):事务内 建 公司 + role=1 账号 并互链(`user.company_id`),**联系人取账号姓名**;登录名查重。
- **机构**(`InstitutionService.save`):事务内 建 机构 + role=2 账号 并互链(`user.institution_id`),联系人取账号姓名。
- **审核/启停联动账号状态**(兑现前端"停用后无法登录"的承诺):
  - 药企 `audit()`:通过(1)→启用账号,驳回(2)/停用(3)→禁用。
  - 机构 `toggleStatus()`:正常(1)→启用,停用(3)→禁用(**仅限 role=2 机构管理员,不动医师**)。
- **删除联动**:药企/机构删除时,其账号**解绑 + 禁用**(`status=0`),不再因账号存在而阻塞删除。
- DTO(`PharmaCompanySaveDTO`/`InstitutionSaveDTO`)新增可选 `username/password/realName`(仅新增消费);前端表单新增时显示"登录账号"分组,编辑时隐藏。

### 5. Flyway 收敛为 schema-only(材料种子迁回 DataInitializer)
- **问题**:原 V2 把"必备材料"当医疗物资种子(除颤器/N95/手术刀…),V3 再追加补丁擦掉重插成正确的报销资料——"插错→删→插对"的补丁链;且材料数据藏在 Flyway,与其余种子(DataInitializer)割裂成两套。
- **整改**:删 `V2`/`V3`,Flyway 只留 `V1__init_schema`(纯建表);材料种子并入 `DataInitializer.seedMaterials()`(照 `seedDict` 样式,自带 `selectCount` 幂等守卫;数据即 V3 那 5 条正确报销资料)。
- **收益**:**所有种子统一在 DataInitializer 一处**。队友改任何数据(含材料)只学一条规矩——"改 DataInitializer + 删库重建";不再有"材料特殊、在 SQL 里",也杜绝再追加补丁迁移。
- 改迁移在这里安全,**前提是删库重建**:`DROP DATABASE` 连带删掉 `flyway_schema_history`,重启从零重跑,无 checksum 不匹配。

1. 停后端。
2. 删库:`DROP DATABASE huiyi;`(连接串 `createDatabaseIfNotExist=true` 会自动重建)。
3. IDEA **Rebuild Project**(JDK 22,勿用 25 EA —— Lombok 会编译失败)。
4. 启动后端 → Flyway 重建表 → 种子写入新数据。
